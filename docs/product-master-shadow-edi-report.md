# Product Master Shadow EDI Report

**Status: READ-ONLY comparison. The exporter was not modified and no export was persisted.**
`product_case_mappings` remains the source the live EDI path reads.

Generated by `scripts/shadow_edi_compare.py` →
`analysis/master-data/product_master_shadow_edi_comparison.csv` and
`…_shadow_edi_summary.json`.

## Architecture

Two exports are built for the same invoice with the **same deterministic formatter**
(`build_pdi_export`, imported unchanged). The only difference is where the master-data input
comes from:

```
CURRENT_LEGACY_EDI      units-per-case  ← product_case_mappings
PRODUCT_MASTER_SHADOW   units-accounted-for ← APPROVED master_commercial_mappings
```

Financial values are never sourced from the Product Master. Quantity, AMOUNT and invoice
totals come from the invoice's own persisted data in both runs, and the comparison asserts
the header record is byte-identical rather than assuming it.

Only **APPROVED** mappings feed the shadow. A line whose item code has no approved mapping
blocks the whole invoice rather than falling back to the legacy value, which would make the
comparison meaningless.

## Difference classification

| Class | Meaning |
| --- | --- |
| `SHADOW_MATCH` | byte-identical output |
| `SHADOW_DIFFERENCE_EXPECTED` | only description differs — PDI product-matches on the UPC, so wording is displayed, not identifying |
| `SHADOW_UNSAFE_DIFFERENCE` | item code, units accounted for, case cost, quantity, AMOUNT or record count differs |
| `SHADOW_BLOCKED` | no shadow export could be produced |

No "better" or "worse" classification exists.

## What this establishes

The shadow machinery is in place and correct — it reuses the real formatter, compares record
counts, item codes, descriptions, multipliers, case costs, quantities, CRLF, byte length and
SHA-256, and separates expected from unsafe differences. What it cannot yet establish is
whether the Product Master would produce equivalent EDI, because no commercial mapping has
been approved. That is a review backlog, not an engineering gap.
